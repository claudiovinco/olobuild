I 12 preset sono dichiarati ma non resi.

megamenu.js espone un campo preset con 12 stili (Modern Clean … Tilt Bar), ma MegaMenuTile.vue non legge mai s.preset: cambiare preset non sposta un pixel. Sotto trasformo i preset in ricette di token — un valore che imposta in blocco nav/typo/hover/CTA — e ne rendo 6 dal vivo. È la singola implementazione che dà più valore alla tile.

04

Implementazioni necessarie

Sei interventi sul codice, dal più importante. Tutti rispettano il vincolo: chiavi salvate invariate.

1

Cablare i preset come ricettealta priorità

MegaMenuTile.vue non legge s.preset: le 12 voci non fanno nulla. Definire una mappa PRESETS (preset → bundle di chiavi già esistenti) e applicarla al cambio. I valori restano override-abili dal cliente — il preset è solo un punto di partenza, non un lucchetto.

// config/megamenuPresets.js — nessuna chiave nuova, solo valori
export const PRESETS = {
  'minimal-line': {
    nav_bg:'', text_transform:'uppercase', letter_spacing:'2',
    font_weight:'600', hover_effect:'underline-grow',
    button_mode:'last', btn_bg:'transparent', btn_radius:{tl:0,tr:0,br:0,bl:0},
  },
  'neon-strip': {
    nav_bg:'#0b1220', text_color:'var(--olo-color-text-invert)',
    active_color:'var(--olo-color-accent)', hover_effect:'glitch',
    panel_open_animation:'blur', panel_bg:'#0e1726',
  },
  /* …altri 10 */
};
// nello store, al cambio preset:
function applyPreset(id){ Object.assign(settings, PRESETS[id] || {}); }
2

Allineare mega_mode: config ↔ componentebug

La config offre auto e css-class. Ma il componente controlla megaMode === 'auto' e === 'all' (valore inesistente), e non gestisce mai css-class: scegliendo "Solo classe mega-menu" nessuna voce diventa mega. Il contratto va riallineato.

// previewItems() — gestire i due valori REALI della config
if (!isButton && megaMode === 'auto' && hasGC) isMega = true;
if (!isButton && megaMode === 'css-class'
    && (item.classes||[]).includes('mega-menu')) isMega = true;
3

Default hardcoded → tokencoerenza

Regola 1 del design language: niente hex grezzi. Oggi i default di top bar e mobile sono fissi: topbar_bg:'#1F2937', topbar_text_color:'#9CA3AF', mobile_bg:'#1e1e2e', topbar_right_cta_color:'#FFFFFF'. Vanno legati ai ruoli cliente (dark/light/text) con fallback via resolveColor, così la top bar segue il brand come il resto.

4

IA dell'inspector per 130 campiUX

È la tile con più chiavi del builder. Senza gerarchia, l'utente si perde. Proposta: preset in cima (riduce il bisogno di toccare il resto), poi gruppi collassabili in ordine di frequenza — Brand & voci → Navbar → Mega-pannello → Top bar → Mobile → Avanzate — e badge "modificato" sui gruppi dove il cliente ha sovrascritto il preset. Stesso pattern dello StyleBoxStack già consegnato.

5

Colonna "promo / immagine" nel pannellofeature

Oggi il mega-pannello rende solo colonne di link (heading + voci). I mega-menu moderni chiudono con una card in evidenza — immagine, articolo, CTA (vedi l'anatomia in alto). Aggiungere un tipo-colonna promo nel megapanel-map: immagine + titolo + link, con placeholder elegante quando vuota (regola 8).

6

Rendere la ricerca expandrifinitura

Esiste search_style:'expand' nei default ma l'anteprima mostra sempre la sola icona statica. Rendere almeno i due stati chiave — icona → campo che si espande inline, e overlay a tutta barra — così l'utente vede cosa sceglie senza pubblicare.

05

Note di metodo

+Perché ricette di token e non CSS per-preset?
Un preset che scrive token resta trasparente e modificabile: il cliente sceglie "Neon Strip", poi cambia solo il colore CTA e tutto il resto regge. Un blocco di CSS dedicato sarebbe opaco, non sovrascrivibile dall'inspector e violerebbe il principio "token-first". Le ricette riusano chiavi che esistono già — zero migrazioni, zero salvataggi rotti.
+Chrome del builder o contenuto della tile?
Tutto ciò che vedi qui è contenuto: usa i token del cliente (primario = rosso brand, override liberi). L'arancio #e8622a dell'inspector — slider, switch device, toggle — resta fisso: è l'identità del prodotto OLObuild e non va toccato.
+Le variazioni sono fedeli al componente reale?
Sì: stessa struttura DOM di MegaMenuTile.vue (bar → nav-item → chevron → uline → tools → panel), stesso set social, stessa logica voce-attiva. Cambiano solo i valori delle chiavi — esattamente ciò che farebbe il preset una volta cablato.
